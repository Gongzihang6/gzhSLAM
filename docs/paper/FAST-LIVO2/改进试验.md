思路二

直接修改原始FAST-LIVO2源码，依旧沿用源代码中的顺序更新策略，按照IMU propgation -> Wheel update -> LIO update -> VIO update -> GNSS update，按照时间顺序逐步执行。

在任意时刻 $t_k$，处理事件顺序建议为：

1. `IMU propagation` 到当前事件时刻
2. `Wheel update`（如果该时刻有）
3. `LIO update`（如果该时刻有）
4. `VIO update`（如果该时刻有）
5. `GNSS update`（如果该时刻有）
