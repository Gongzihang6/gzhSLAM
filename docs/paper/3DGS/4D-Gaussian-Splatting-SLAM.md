# 4D Gaussian Splatting SLAM

## 简介

最初的 3DGS 只能重建静态场景，如果场景中存在动态物体，一方面，会影响 colmap 的位姿结算（干扰图像匹配），另一方面，动态物体处的高斯球会出现模糊、重影等现象，之前的处理方法是把动态物体视为干扰因素，通过一个语义分割的前处理去除动态物体，但是这样又会导致重建的场景存在空洞。

因此本文提出了一种高效架构，不再将动态物体视为干扰因素，而是利用一系列 RGB-D 图像，在未知场景中增量式的跟踪相机位姿，并建立 4D 高斯辐射场。首先，通过生成运动掩码，得到每个像素的静态与动态先验。为了消除静态场景的影响，并提高学习动态物体运动的效率，我们将高斯基元划分为静态和动态高斯集合，同时利用稀疏控制点、结合 MLP 来建模动态高斯的变换场。为了更精确的学习动态高斯的运动，设计了一种新的 2D 光流图重建算法，用于渲染相邻图像间动态物体的光流，并进一步结合传统光度和几何约束（深度）来监督 4D 高斯辐射场的优化。实验结果表面，该方法在真实环境中实现了鲁棒的位姿跟踪和高质量的视图合成性能。

我们的方法以增量方式在线估计相机位姿并更新高斯表示，从而对未知且高度动态的环境具有鲁棒性。通过利用 RGB-D 输入中的深度信息，我们在保持高效计算的同时提高了几何精度。与依赖后处理或显式运动分割的先前工作不同，我们的方法将运动线索自然的融入场景表示当中，从而在不丢弃动态内容的情况下实现无缝重建。

本文主要贡献如下：1、提出了一种新颖的 4D Gaussian Splatting 流程，用于在高斯辐射场中固定并表示动态场景；2、我们将高斯基元划分为静态和动态高斯，并引入稀疏控制点，结合 MLP 来建模动态高斯的运动；3、提出了一种新颖的 2D 光流渲染算法以提升 4D 高斯场的性能，我们分别从动态高斯点（Dynamic GS）和预训练模型中估计 2D 光流图，并将其作为约束用于学习动态高斯的运动。

## 核心方法

### 初始化

和其他基于高斯泼溅的 SLAM 系统类似，本文的 3D 高斯椭球体也包含均值 $\mu$，协方差矩阵 $\Sigma$（由尺度 Scale 和旋转 Rotate 确定），不透明度 $\alpha$，以及颜色 $c$ 等参数，除此之外，我们进一步为每一个高斯基元引入了 $dy$ 这个属性，用来表示这个高斯是静态的还是动态的。`dy` 是 Dynamic 的前两个字母。因此，最终的高斯表示就是：$\mathscr{g}=[\Sigma \: \mu \:\alpha\: c\: dy]$

通过深度图的深度值，将像素点反投影到 3D 空间之后，根据这些真实 3D 点坐标来初始化高斯基元，然后通过将高斯基元 render 到 2D 图像上，通过渲染图像和真实图像的差异，就可以通过梯度反向传播，将误差流动到高斯基元上，来更新高斯属性。具体来说，渲染图像上的每一个像素的颜色，可以用如下公式描述：

$$
C(p)=\sum_{i = 1}^nc_i\alpha_i \prod_{j}^{i-1}(1-\alpha_j)
$$

具体来说，就是给定一个相机视角，我们渲染这个相机视角下的二维图像，原理是根据相机视角，在相机光心位置构建一个虚拟的图像平面， 3D 高斯球的三维中心点（均值 $μ_W$），通过相机的投影矩阵变换，直接就变成了 2D 屏幕上的一个像素中心点坐标（均值 $μ_I$）; 3D 高斯球在三维空间中的形状和旋转（3D 协方差 $Σ_W$），通过相机变换的仿射近似雅可比矩阵（Jacobian J）和旋转矩阵 W，精确地转换为 2D 屏幕上的扁平椭圆形状（2D 协方差 $Σ_I$）。计算公式为 $Σ_I=JWΣ_WW^TJ^T$，通过这两步投射，就可以把所有高斯球拍扁到像素平面上，就可以准确获取每一个 3D 高斯球在当前相机视角下，会落在屏幕的哪个区域，以及会覆盖什么形状、多大面积的像素。

渲染的优化与 Alpha 混合。系统首先将整个 2D 屏幕划分为 16×16 像素的网格块（Tiles），然后根据相机的视场角范围，构建视锥体，直接去除视锥体范围以外的高斯球；所有完全不在相机视野内的高斯球会被直接丢弃（Frustum Culling）。对于留在视野内的高斯球，系统会根据它们投影后在屏幕上的位置，将它们分配给相交的网格块处理。接着，针对每一个被分配的高斯球，系统结合其所在的网格 ID 和它距离相机的真实 3D 深度（View space depth）生成一个特定的键值（Key），并在 GPU 上使用极快的基数排序（Radix Sort）将所有高斯球按照 从近到远 的顺序排好。

现在，对于屏幕上的任何一个像素，GPU 的线程块只需要去查看该像素所在的 16×16 网格块（Tile）。在这个网格块里，系统已经为你准备好了一个该区域独有的、严格按照深度“由近及远”排好序的高斯球列表。线程块只需 从前向后（Front-to-back） 遍历这个列表，提取出覆盖当前像素的高斯球，根据它们投影后产生的 2D 高斯概率密度（也就是它们在像素点位置的透明度贡献），不断累加颜色和不透明度 $α$。提前终止（Early Stopping）： 在从前向后累加的过程中，只要当前像素累积的 $α$ 值接近 1（达到 0.9999），就说明这个像素已经被近处的不透明物体完全遮挡了。此时，线程会立即终止该像素的计算，直接抛弃后面的高斯球。

3DGS 是 以高斯球为主体，利用相机几何矩阵，直接把 3D 空间的高斯球“拍扁”投射到 2D 屏幕的具体像素上；然后通过将屏幕分块并按深度排序，极大地缩小了每个像素需要考虑的高斯球范围。最后，通过顺序叠加这些覆盖在像素上的 2D 斑块颜色，高效地完成了图像的生成

至于每个像素的深度 $D(p)$ 和不透明度 $O(p)$，和颜色渲染的原理一样，都是用 alpha-blending，只不过属性由颜色 $c_i$ 变成了深度 $d_i$ 和不透明度 $\alpha_i$

$$
D(p)=\sum_{i = 1}^nd_i\alpha_i \prod_{j}^{i-1}(1-\alpha_j)
$$

$$
O(p)=\sum_{i = 1}^n\alpha_i \prod_{j}^{i-1}(1-\alpha_j)
$$

高斯球的动态/静态属性初始化。论文使用预训练模型 yolov9 来获取运动掩码，然后通过深度初始化相应的高斯球，并设置 dy 属性为 true，标识为动态；对于 yolov9 无法正确分割的序列（包含动态物体，但是有遮挡或者模型没有见过），我们结合光流和预训练模型来生成运动掩码。

### 运动预测

如果让网络去单独预测几十万个动态高斯球各自的运动轨迹，不仅算力会瞬间爆炸，而且物体在运动时会发生“撕裂”（因为没有保持物理结构的连贯性）。 为了解决这个问题，作者从另一篇论文 SC-GS 中汲取了灵感，引入**稀疏控制点机制**来预测运动。以前的方法（如 SC-GS）需要经过漫长的离线预训练才能找到这些控制点，这在讲究实时的 SLAM 中是行不通的。因此，这篇论文直接利用第一帧图像里的二维运动掩码区域，在线、快速地初始化出这批稀疏控制点。

有了“骨骼（控制点）”之后，系统需要知道它们随着时间怎么动。论文设计了一个轻量级的多层感知机网络（MLP $Ψ$）。 对于任意一个控制点 $P_k$，只需把它的坐标和当前的时间戳 $t$ 输入给这个 MLP，网络就会输出一个 6 自由度（6-DoF）的变换矩阵，也就是该控制点在 $t$ 时刻的旋转（$R_t$）和平移（$T_t$）。这相当于用神经网络算出了骨架随时间的运动轨迹。

骨骼（控制点）动了，依附在它周围的血肉（几十万个动态高斯球 $G_{dy}$）该怎么跟着动呢？论文采用了 3D 动画中非常经典的线性混合蒙皮技术（Linear Blend Skinning, LBS）。

**找邻居 (KNN Search)：** 在标准空间（Canonical space）里，对于任何一个单独的动态高斯球，算法会利用 $K$ 近邻（KNN）搜索，找到距离它最近的 $K$ 个控制点。**算权重 (RBF Weighting)：** 距离高斯球越近的控制点，对它的牵引力应该越大。因此，算法使用高斯径向基函数（RBF）来计算这 $K$ 个控制点对该高斯球的插值权重。计算最终形变： 结合这些权重，以及那 $K$ 个控制点的 6-DoF 变换（$R_t,T_t$），算法就可以平滑地插值出这个动态高斯球最终的位置（$μ$）平移、旋转（$R$）扭曲、甚至尺度（$S$）的拉伸与缩放

模型不需要去死记硬背每一个像素点怎么动，它只需要通过 MLP 学会那几个核心控制点在时空中的 6-DoF 轨迹，然后再通过 LBS 插值算法，像“扯线木偶”一样把周围的动态高斯球顺滑地拉扯过去。这不仅极大地降低了 4D 动态场景重建的维度和显存消耗，还因为 LBS 蒙皮的物理连贯性，保证了渲染出的行人、车辆在运动时不会发生空间上的破碎或伪影。

### 跟踪

为了避免动态物体对相机定位的干扰，我们从高斯泼溅渲染中剔除掉动态高斯球，只渲染静态属性高斯球，得到绝对静止的场景。因为在传统SLAM中，如果相机盯着一个向前走的人来计算自己的位置，算法会误以为是相机在向后退，为了避免这种误判，论文采取了如下的静止隔离策略：

-   在虚拟渲染端，当系统视图渲染当前视角的画面来和真实画面做对比时，它故意不渲染任何动态高斯球，画面完全由静态高斯球生成；
-   在真实观测端，结合yolov9和光流生成的运动掩码（Motion Mask M），系统会在输入的真实RGB-D图像上把动态物体直接挖空；

通过这种方式，算法强行建立了一个“纯静态的虚拟世界”与“纯静态的真实观测”之间的对比，从而排除了所有运动物体的干扰，确保优化出的相机位姿是绝对精准的。

优化过程中，我们使用渲染的外观和深度图，与其观测值之间的L1损失，其中运动掩码$\mathcal{M}$用于从输入图像中去除动态物体，以实现鲁棒的相机位姿定位性能。
$$
L_t = \sum_p \mathcal{M}\left(\lambda O(p)L_1(C(p)) + (1 - \lambda)L_1(D(p))\right)
$$
系统通过最小化这个损失函数L_t来不断微调优化相机的6-DoF位姿和曝光参数。具体来说，我们遍历图像上的每一个像素点p，如果像素p在运动物体上，M=0，整个式子归零；如果p是静态背景，则M=1，参与计算。L_1(C(p))是颜色光度误差，比较渲染出来的颜色和相机拍到的真实颜色的绝对差值；L_1(D(p))是深度几何误差，比较渲染出来的3DGS深度和传感器测到的真实深度的绝对差值；\lambda是一个固定权重，用来平衡颜色误差和深度误差在总损失中的占比；O(p)是累积不透明度，公式中O(p)乘在了颜色误差上，这意味着如果在当前视角下，这块区域的高斯球非常稀薄、半透明（重建得不好），那么它的颜色误差对相机位姿优化的贡献就会被降低，系统会更信任那些已经重建的很厚实（不透明度高）的区域。

注意，针对深度误差L_1(D(p))，必须满足O(p)>0.95，也就是3D高斯地图在这个射线上已经累积了极高的不透明度，即这里有一堵实实在在的墙或者表面。如果O(p)很低，说明这里可能是视线边缘的雾状伪影，用它的深度来优化相机位姿会导致严重漂移；必须满足d(p)>0，也就是真实的深度传感器在这个像素上确实测到了有效深度。
